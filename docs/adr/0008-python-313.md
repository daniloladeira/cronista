# ADR-0008 · Python 3.13

- **Status:** aceito
- **Data:** 2026-08-12
- **Requisitos relacionados:** RNF-C03

## Contexto

A máquina tem Python 3.14 e 3.13 instalados. O 3.14 é a versão mais recente e seria o padrão natural.

O ecossistema de aprendizado de máquina costuma levar meses para publicar pacotes compilados para uma versão nova de Python. `ctranslate2`, base do `faster-whisper`, é pacote compilado com dependências de CUDA — exatamente o tipo que demora mais a acompanhar. Sem pacote pronto, resta compilar localmente no Windows, o que exige toolchain de C++ e costuma consumir uma tarde inteira antes de qualquer linha do projeto ser escrita.

## Decisão

Usar **Python 3.13** no ambiente virtual do projeto.

## Verificação

A escolha foi validada empiricamente antes de ser registrada: o ambiente foi criado em 3.13 e as dependências de captura de áudio instalaram sem compilação. A captura de loopback foi testada e funcionou.

## Consequências

**Positivas.** Compatibilidade ampla com o ecossistema. Nenhuma compilação local. Ainda é versão recente, com suporte por anos.

**Negativas.** Fica uma versão atrás da mais nova, sem acesso a recursos do 3.14. Um deles é relevante: o 3.14 traz geração de UUIDv7 na biblioteca padrão, o que aqui exige uma função própria de cerca de dez linhas.

## Gatilho de reversão

Quando `ctranslate2` publicar pacote pronto para 3.14 e o restante das dependências acompanhar. A migração deve ser trivial: recriar o ambiente e substituir a função própria de UUIDv7 pela da biblioteca padrão.

Se, por outro lado, o 3.13 apresentar conflito insolúvel, o caminho é **descer** para 3.12, não subir.
